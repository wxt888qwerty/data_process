# 交付批次质检驳回分析

## 判断

最可行动的信号需要按车队组合：三支车队对标定年龄 ≥12 分钟触发；西部高架专项组的标定年龄信号为负，但有效帧评分 ≤3 的训练期规则在后续验证也有正净值。组合规则的验证净值为 **+1,225 小时**，比只使用标定年龄的分层规则多 **210 小时**。西部高架专项组验证期只有 12 个被标记批次，证据较少，所以这部分应先影子观察或人工复核试点。

## 数据与口径

- 只使用题目发放的 `doc/delivery_batches.csv`，没有补造数据。
- 原始 1,085 行中有 **52 行完全重复**。删除完全重复行后，得到 1,033 个唯一 `batch_id`；没有剩余的重复 ID。
- 去重后有 37 个 `status_ok` 为空的批次，按题意视为质检中并从失败率分析中排除。其余 996 批中，驳回 130 批、通过 866 批，基准驳回率 **13.1%**。
- 按时间戳自带的时区解析，计算打包时标定年龄（分钟）。训练/验证切分按 `Asia/Shanghai` 日期，避免把 `+08:00` 时间戳误当 UTC 日期。
- 先用本地日期早于 2026-09-06 的已出结果批次选阈值：最大化 `75 × 被标记的历史驳回数 − 20 × 被标记的批次数`；并列时取更高阈值以减少检查量。由此选出 **标定年龄 ≥12 分钟**。之后日期（2026-09-06 至 2026-09-07）仅用于时间外验证。

## 结果

“检查命中率”是被标记批次中的历史驳回比例；“驳回召回率”是历史驳回中被标记的比例。净工时为按题目成本口径计算的**理论上限**：假设每个被标记批次都做一次 20 小时提前检查，并且每个本来会被驳回的命中批次都因此避免一次 75 小时返工。

| 数据切片 | 批次 | 被标记 | 标记后驳回 | 检查命中率 | 驳回召回率 | 理论净工时 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 早期训练集（截至 09-05） | 714 | 213 | 67 | 31.5% | 77.0% | +765 小时 |
| 后续时间外验证（09-06 至 09-07） | 282 | 79 | 31 | 39.2% | 72.1% | +745 小时 |
| 早期训练集：分车队规则 | 714 | 150 | 63 | 42.0% | 72.4% | +1,725 小时 |
| 后续时间外验证：分车队规则 | 282 | 58 | 29 | 50.0% | 67.4% | +1,015 小时 |
| 早期训练集：分车队组合规则 | 714 | 166 | 72 | 43.4% | 82.8% | +2,080 小时 |
| 后续时间外验证：分车队组合规则 | 282 | 70 | 35 | 50.0% | 81.4% | +1,225 小时 |
| 全部已出结果批次（描述性统计） | 996 | 292 | 98 | 33.6% | 75.4% | +1,510 小时 |

训练期按车队分别核算 12 分钟规则：东部常态路测队标记 57 批、命中 23 次驳回（+585 小时）；北部夜间采集队 37 批、命中 16 次（+460 小时）；南部封闭测试区 56 批、命中 24 次（+680 小时）；西部高架专项组 63 批只命中 4 次（-960 小时）。因此，只对前三支车队启用年龄规则。训练集再单独筛选出西部高架专项组的 `valid_frame_ratio <= 3` 规则（16 批命中 9 次驳回，+355 小时），后续验证中 12 批命中 6 次（+210 小时）。组合策略相对仅年龄的分层策略，多做 12 次检查并多命中 6 次历史驳回，净增 **210 小时**，召回率由 67.4% 提至 81.4%。但这个补充规则验证样本很小，不能当作已确认的稳定规律。

组合策略验证集的 70 次检查中有 35 次历史驳回；要实现实际正净值，至少需避免其中 19 次驳回（`ceil(70 × 20 / 75) = 19`），即约 27.1% 的全部检查，或 54.3% 的这 35 次历史驳回。真实收益仍取决于提前检查能否避免驳回、实际检查耗时以及后续车队表现；不得把理论净工时当作已节省工时。

作为次要信号，`valid_frame_ratio <= 2` 在全量数据中标记 78 批、命中 23 次驳回，召回率 17.7%；训练集命中率只有 25.0%，低于理想完全拦截下的盈亏平衡线 `20/75 = 26.7%`。因此不把它单独设为主拦截规则。

## 建议

先在东部常态路测队、北部夜间采集队和南部封闭测试区试行：标定年龄达到 12 分钟时暂停提交，执行标定同步和轻量复检。西部高架专项组可先影子运行 `valid_frame_ratio <= 3` 提示并人工复核，样本扩大后再决定是否自动拦截。所有批次仍须经过既有最终质检。记录每次检查耗时、是否发现问题、复检后是否仍被驳回和实际返工工时；组合规则在 70 次检查中至少要实际避免 19 次驳回才有正净值。

## 复现

需要 Python 3.10+ 和 pandas。仓库根目录运行：

```bash
python -m pip install -r requirements.txt
python analyze.py
```

脚本会在终端打印完整 JSON，并生成/覆盖 `analysis_results.json`。也可指定输入和输出：

```bash
python analyze.py --input doc/delivery_batches.csv --output analysis_results.json
```

阈值选择、训练期分车队筛选、去重、待质检批次排除、时区处理和时间外验证均在 `analyze.py` 中实现。

## 局限与下一步

这是一段约一周的观察数据，没有质检驳回原因、提前检查实际耗时或干预后的结果。标定陈旧可能是原因，也可能与未记录的采集/打包问题共同出现；历史相关性不能证明同步动作会消除失败。建议先小范围试行并记录上述字段，再用实际避免的驳回和工时核算收益。样本中的待质检批次未纳入失败率；重复行按完全相同行删除。
